# 阶段 1：检查、规划、冻结

本阶段只交付导演脚本与机器点位表。未经用户明确批准，不创建 Remotion 工程、不制作 MG、不合成视频。

## 1. 检查输入

1. 记录 `video`、`subtitles`、可选 `screen_video` 和 `output_dir`，从口播文件名推导 `project_id`。
2. 用 `ffprobe` 检查视频可解码性、分辨率、帧率、时长和音轨。
3. 完整检查 SRT：序号连续、时间码递增且不重叠、最后一条不超过视频时长；抽查开头、中段和结尾的音画对齐。系统性错字、术语无法判断或持续漂移时停止。
4. 双视频模式在开头、中段、结尾抽查同步和等长；持续漂移必须先在本 Skill 之外修复。
5. 把输入时间线标为 final。后续每个点位同时记录最终字幕 ID 范围、字幕原文和起止秒。

若用户没有 SRT，路由到独立转写流程，得到并核对最终 SRT 后再回来。不得在本工程实现或宣称 ASR。

## 2. 按语义规划完整画面时间线

先读完整字幕，切成章节或语义大块，再把每段标为：

- `screen-demo`：点击、输入、拖动、软件操作、代码、表格或结果；
- `visual-explanation`：关系、步骤、对比、数据或示意；
- `theory`：概念、框架、因果、流程、抽象判断；
- `talking-head`：个人表达、情绪、故事、强调和自然过渡；
- `transition`：章节衔接或很短的补充句。

不要只列 MG 段。单视频模式规划“口播原画面 ↔ MG”；双视频模式规划“口播原画面 ↔ 录屏 ↔ MG”。

| 内容 | 默认画面 | 边界 |
|---|---|---|
| 真实屏幕操作 | 录屏主体 + 右下角圆形人像 | 不遮关键点击、菜单、代码、表格和结果 |
| 步骤、对比、数据、关系 | 全屏 MG + 右下角人像 | 演变化、顺序和关系，不堆长文 |
| 理论、框架、抽象关系 | 全屏 MG + 右下角人像 | 视觉化关系，不做换页 PPT |
| 故事、态度、情绪 | 人像全屏 | 不为密度强行加 MG |
| 段落过渡 | 人像或轻量标题/MG | 保持节奏 |

补充规则：

- 不伪造输入里不存在的软件操作、界面、数据或事实。
- `screen-demo` 对全屏 MG 有否决权；原画面承担重要情绪或肢体表达时保留人像。
- 每个 MG 只解释一个核心观点，通常覆盖完整的 8–40 秒观点；无关观点拆开。

## 3. 产物

写入：

- `MG导演脚本.md`：ID、字幕锚点、内容类型、画面选择、表达目的、2–5 个视觉节拍、简短屏幕文案、进出场、人像策略、录屏保护、选择理由和状态。
- `mg-placement-plan.v1.json`：`project_id`、源文件、总时长、每个 cue 的 `id/start_seconds/end_seconds/srt_range/spec`、录屏窗口、人像窗口、章节、`presenter_policy` 和状态。

末尾汇总总时长、MG/人像/录屏占比与所有待确认假设。状态先写 `draft`，把两个文件交给用户。只有用户明确说“确认、批准、按这版执行”等同义表达后才改为 `approved`，然后停止本阶段。
